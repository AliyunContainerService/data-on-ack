Ray on ACK · 生产实践

把 Ray 算力，稳稳跑在生产级 ACK 上

十篇经过生产验证的实战指南：从第一个 RayCluster，到 eRDMA 上的高性能传输——每一步都有可直接复制的 YAML 与命令。

ray-on-ack — kubectl 
# 通过 KubeRay 一键部署 RayCluster（1 head + 1 worker）
$ kubectl apply -f ray-cluster.yaml
raycluster.ray.io/demo-ray-cluster created
$ kubectl get pods
demo-ray-cluster-head-mgdnb                1/1   Running
demo-ray-cluster-worker-group-worker-lvbr2 1/1   Running
$ kubectl exec -it $HEAD_POD -- ray status
Idle: 1 worker-group, 1 headgroup · 2 CPUs ready

GPU 共享与弹性调度

eRDMA 高性能传输

Capabilities

从开发到上线，全链路覆盖

交互式开发

Jupyter 与 VSCode Notebook 秒级创建，代码经 Commit Agent 自动同步，环境可复现。

分布式训练

集成 Arena 与 Ray，支持 PyTorch / TF 多机多卡训练，任务排队与优先级调度开箱即用。

模型推理服务

模型一键部署为在线服务，支持灰度与弹性伸缩，从实验到生产一步到位。

弹性配额

ElasticQuotaTree 多级配额管理，团队间资源共享与隔离兼得，GPU 利用率最大化。

成本洞察

按团队、任务维度追踪 GPU 成本，账单归因清晰，让每一份算力投入都有回响。

企业级治理

RAM 身份集成、用户组隔离、审计与备份恢复，满足生产环境的合规与稳定性要求。
